# ระบบสรุปคอมเมนต์แจ้งปัญหา
ศูนย์ปฏิบัติการน้ำท่วม กทม. · สำนักงานเขตทวีวัฒนา

รวบรวมคอมเมนต์จากโพสต์ Facebook (CSV จาก extension "Comments Exporter") คัดเฉพาะเรื่องแจ้งปัญหา/ขอความช่วยเหลือ
แยกหมวดตามภารกิจฝ่าย จัดความเร่งด่วน ดึงสถานที่ แล้วแสดงเป็น Dashboard และรายงาน

- **หน้าเว็บ:** GitHub Pages (โฟลเดอร์ `docs/`) — ไม่มีเซิร์ฟเวอร์ของเราเอง
- **ข้อมูล + ล็อกอิน:** Supabase (Postgres + Auth) — สิทธิ์บังคับที่ฐานข้อมูลด้วย Row Level Security

> repo นี้เป็น public: มีแต่โค้ด **ไม่มีข้อมูลผู้แจ้ง** · ข้อมูลอยู่ใน Supabase และอ่านได้เฉพาะผู้ที่ผู้ดูแลอนุมัติแล้ว

## ติดตั้ง (ครั้งเดียว)
1. **สร้างโปรเจกต์ Supabase** ที่ supabase.com → New project (Region: Southeast Asia (Singapore))
2. **สร้างตาราง:** Supabase → SQL Editor → วางไฟล์ [`supabase/schema.sql`](supabase/schema.sql) ทั้งไฟล์ → Run
3. **ตั้งค่าล็อกอิน:** Authentication → URL Configuration
   - Site URL = ที่อยู่ GitHub Pages ของระบบ (เช่น `https://<user>.github.io/thawi-flood-comments/`)
   - Redirect URLs เพิ่มที่อยู่เดียวกัน
4. **เชื่อมหน้าเว็บ:** Project Settings → API → คัดลอก *Project URL* และ *anon / publishable key*
   ใส่ใน [`docs/static/config.js`](docs/static/config.js) แล้ว commit
   (**ห้าม**ใส่ `service_role` / secret key)
5. **เปิดเว็บ → สมัครใช้งาน** — คนแรกที่สมัครจะเป็น *ผู้ดูแล* อัตโนมัติ
   คนต่อไปจะ "รออนุมัติ" จนผู้ดูแลกำหนดสิทธิ์ในหน้า ตั้งค่า → ผู้ใช้งาน

## ใช้งาน (ผู้ดูแล)
1. **โพสต์ & นำเข้า** → เพิ่มลิงก์โพสต์ Facebook ที่ต้องติดตาม
2. เปิดโพสต์ → กด extension Comments Exporter → Export CSV
3. กด **นำเข้า CSV** ที่โพสต์นั้น (อัปโหลดซ้ำได้ ระบบเพิ่มเฉพาะคอมเมนต์ใหม่ · โพสต์ที่ไม่ได้ดึงเกิน 6 ชม. ขึ้น ⚠)
4. **ตรวจทาน**: ยืนยัน/แก้หมวด/ตัดทิ้ง · ไล่ดูแท็บ "ไม่เข้าหมวด" และ "ต้องเปิดดู"
5. **รายการปัญหา**: อัปเดตสถานะ (บันทึกทันที) และหมายเหตุ — ทุกการแก้ไขบันทึกว่าใครแก้เมื่อไร
6. **Dashboard**: ส่งออก *สรุปผู้บริหาร* (ไม่มีชื่อ) หรือ *รายงานปฏิบัติการ* (ภายใน มีชื่อ/ลิงก์)

## สิทธิ์
| บทบาท | ทำอะไรได้ |
|---|---|
| ไม่ได้ล็อกอิน / รออนุมัติ | ไม่เห็นข้อมูลใดๆ |
| ผู้ดู | ดู Dashboard รายการปัญหา และส่งออกรายงาน |
| ผู้ดูแล | ทุกอย่าง: นำเข้า ตรวจทาน แก้ไข ตั้งค่า keyword อนุมัติผู้ใช้ ลบข้อมูลส่วนบุคคล |

## โครงสร้าง
| ไฟล์ | หน้าที่ |
|---|---|
| `supabase/schema.sql` | ตาราง, RLS, ประวัติการแก้ไข, ฟังก์ชันนำเข้า/สถิติ/ค้นหา (รันซ้ำได้) |
| `docs/static/classifier.js` | keyword เริ่มต้น หมวด เกณฑ์ความเร่งด่วน และการดึงสถานที่ |
| `docs/static/backend.js` | เชื่อมต่อ Supabase, อ่าน/แปลงข้อมูลนำเข้า, ส่งออก CSV |
| `docs/static/app.js` | หน้าจอทั้งหมด |
| `docs/static/config.js` | Supabase URL + anon key |

## PDPA
- ไม่เก็บรูปโปรไฟล์/เพศ (ตัดทิ้งในเบราว์เซอร์ก่อนส่ง)
- จบสถานการณ์แล้ว: ตั้งค่า → *ลบข้อมูลส่วนบุคคล* (ลบชื่อและลิงก์ผู้แจ้ง เก็บสถิติไว้)
- ถอดสิทธิ์คนที่ย้าย/ลาออก: ตั้งค่า → ผู้ใช้งาน → เปลี่ยนเป็น "รออนุมัติ / ระงับ"
